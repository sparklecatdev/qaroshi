# Qaroshi 9.2: semantic adjudication and compositional-readiness protocol

**Scope.** Standard 9.2 addresses the three critical editorial engineering issues after the 9.1 500-draft milestone: a definitive current reference, a stronger all-500 meaning and form audit, and fresh test items that require compositions not present in the original fixed benchmark. The release **does not substitute editor confidence for human comprehension**. Every 9.1 translation remains a candidate until independent readers establish its meaning.

## 1. The grammar now has one current entry point

The [unified editorial grammar](grammar.md) embeds **all 90 chapters** of the existing 8.0 grammar, the adopted 8.1 polar-question refinement, and the entire text of each documented 8.4–9.1 amendment. It is generated byte-for-byte from unchanged source files by:

    python tools/stress92/build_grammar.py --write

CI uses:

    python tools/stress92/build_grammar.py --check

The [registry](../../data/standard_9_2/amendment_registry.json) defines amendment status and precedence and lists the eight corrected 9.0 consent morphology cases. The first page is a current conflict-resolution table: finite suffix order, case roles, negative scope, temporal *not-until*, modal entailment, reported evidence, speech acts, and metaphor. **Editorial authority for new writing is not proof that the proposed lexemes are historically speaker-attested.** Every source is still linked and its historical wording is retained.

## 2. Audit all 500 original proposed translations, not just presence

Run:

    python tools/stress92/semantic_audit.py

This independently reads the unchanged original English feature labels, the original 9.1 candidate ledger, the canonical dictionary, and the 9.1 lexical-sense overlay. It does **not** use the candidate-producing function as its expected output. For each English item it checks:

- Source-domain intended speech act: affirmative, negative, polar interrogative, reported, inferred, doubted, counterfactual, and conditional.
- The correct number and role of distinct events: particularly **not until**, matrix nonassertion, actual consent or explicit revocation, and fictive/literal interpretation.
- Visible operator evidence for clause topology and role selection (passive agent versus physical tool, relative marker, quotation and counterfactual marker).
- Explicitly documented lexical source IDs, overlay statuses and actual use of newly coined word forms, without promoting rejected lexical proposals.
- Surface morphology ordering and independent sentence resonance, including quotes containing independent sentences.

It writes **500 item-specific** rows to the review CSV and an accompanying human decision queue. An issue is labeled *structural blocker* only when a check is demonstrably violated. Ambiguous lexical senses and the truth-condition fidelity of a superficially plausible sentence are **not** automatically passed; they remain review risks. Crucially, passing this checker is **not** independent semantic equivalence, an idiomatic-usage rating, or evidence of native proficiency.

**Evaluation classes must remain separate:**

| Class | Interpretation | 9.2 release requirement |
| --- | --- | --- |
| Draft exists | A proposed Qaroshi string exists | All original 500 |
| Structure/source check | A bounded automated source and operator review | All original 500, with explicit blockers and warnings |
| Editorial meaning decision | A named reviewer explicitly compared all semantic factors, with counterexamples | Never inferred from code tests |
| Independent interpretation | A person who did not see the target English independently paraphrased Qaroshi | No invented respondents |
| Unrestricted conversational competence | Speakers spontaneously compose, understand and repair novel conversation | Not established by this release |

The earlier simple audit flagged eight inherited \`-ki-te\` forms and the 9.1 versioned view corrected them to \`-te-ki\`. The 9.2 checker keeps testing that exact ordering on all 500 strings. It does not overwrite any 8.0–9.1 source or silently rewrite unrelated existing drafts.

## 3. New held-out compositional productivity benchmark

Run:

    python tools/stress92/heldout.py
    python -m unittest tests.test_standard_9_2 -v

The 9.2 suite uses **ten independently documented Qaroshi event propositions** and **ten distinct endpoint propositions** from the 9.1 motion frames. Each main event is paired with each endpoint from a *different* scenario: **10 × 9 = 90 new event pairs**. Each pairing appears under five distinct independently authored English and Qaroshi contrastive conditions:

1. Event B happened **after** event A (\`ana\`), with both asserted.
2. Event A happened **before** event B (\`ëna\`), with both asserted.
3. Event A occurred **when** event B occurred (\`yaro\`), with both asserted.
4. **Someone told the speaker** event B followed event A. The report is an event; the underlying sequence is **not independently asserted**.
5. A real **yes/no question** asks whether event A happened before B. Neither event is asserted by the question.

This produces **450 unique cross-family full-sentence pairs**, none reusing an original English challenge or an original Qaroshi candidate string. Crucially, these are *combinations*, not 450 freshly invented dictionary words. A separately implemented, bounded **source-event parser** in \`tools/stress92/parse_temporal.py\` must recover the event identities, order, assertion, reported-source scope, and question scope from the generated surface Qaroshi.

The tests must also reject or reinterpret adversarial alterations: reversing temporal conjunctions; removing reporter attribution; confusing witnessed fact with report; changing an event's actor or object; stripping a question ending; changing a past verb into a future verb in a licensed past frame; or omitting the affirmative later event required by an English *not until* statement.

This is a **genuine held-out pairing test with respect to the original 500 fixed English prompts**, but it uses **known source-event licenses** and a **restricted interpreter**, not a general syntactic parser or free English translation engine. Reuse of known events across new pairs is explicitly permitted; the benchmark does not test broad unsanctioned noun/verb interchange or new word meaning discovery. It remains a repeatable **editorial/software** stress test, not evidence that real learners understand the expressions.

## 4. External comprehension remains the next separate gate

The blind-reading protocol already exists in the [8.0 review procedure](../standard_8/REVIEW_PROTOCOL.md). A proper 9.2 reader study should take a randomized and held-back subset from **both** the original 500 and new 450, with the English key physically isolated from participants. Invite consenting people who did not draft the answers, ideally five or more as described in the earlier protocol. Do not collect real names, health, account numbers, addresses or recordings without separate opt-in.

Ask readers for literal English paraphrases and annotate: (a) the actor and affected patient, (b) time and reference identity, (c) report versus fact, (d) negation versus nonassertion, (e) permission, ability and obligation, and (f) metaphor versus literal-world claim. Score against the English key afterward; record disagreement and ambiguous alternatives, including failures where the original English itself was awkward or ambiguous. Freeze the evaluation prompts **before** participants respond; correcting a failed question after seeing answers invalidates that test's blind status.

**As of this edition, 0 independent human interpretations are in the repository.** The model author cannot self-attest independent comprehension, and no passing test should silently fill that field.

## 5. Reproduce the release

    make stress92
    python -m unittest discover -s tests -q
    python tools/maintenance/audit_repository.py --site

Expected local generated materials (all under ignored \`data/stress92/\`):

- \`semantic_review_500.csv\`: each original case, operator/source checks, independent-readable warnings and empty human fields.
- \`editorial_action_queue.csv\`: one entry per proposed translation, including explicit high-priority blockers and empty adjudication slots.
- \`semantic_review_summary.json\`: blocker counts and explicit independent-reader zeros.
- \`unseen_compositions_450.csv\`: source IDs, original-independent English target, Qaroshi sentence and scoped formal semantics.
- \`unseen_summary.json\`: new-pair counts and repeated warning against human validation claims.

GitHub CI publishes the full two ledgers separately. Old 9.1 artifacts and frozen source hashes remain available. If a structural issue remains, classify and repair it in a **new versioned overlay**, preserving historical forms; never lower the bar by silently accepting a malformed sentence.
